# Run and log a workout

Work from the repository root. Follow `AGENTS.md` for setup status and onboarding. Read `docs/plans-and-sessions.md` and the saved plan for this session. Read an existing checkpoint when resuming. If no approved saved plan exists, use repwerk-plan first. The plan is the immutable baseline, referenced by path and ID in the result. Use a unique session ID and write `sessions/<session-id>.json` at finish or explicit checkpoint. Preferences are not barriers to recording work actually done.

- On arriving at each circuit, preview a minimal table: exercise, counts (rounds × sets), and targets (reps or duration, load, effort). Omit setup instructions and rest from this preview. During work, show only a compact next-action table row with block/round/set, exercise, target/load and any rest; do not echo each logged result. Use prose only for a clarification or change.
- Keep live work in context. Record clear natural-language results without confirmation; an otherwise clear result without a stated status is completed. Parse `12/3` as 12 reps at 3 RIR when RIR is the applicable effort measure, and `12/4 30lb` as 12 reps at 4 RIR with a 30 lb load override. For omitted values, use exact values from the effective prescription (including agreed session-specific changes). Do not invent exact reps from a range: ask for the rep count when omitted. An omitted effort target range may be recorded as that range rather than a single value. Ask briefly when genuinely ambiguous.
- `same` copies reps, effort and load from the most recent completed set of the same exercise and side, then applies any explicit override (for example, `same 27.5lb`). Do not copy status or notes. If there is no comparable completed set, ask. By default, a single result for a unilateral movement applies to both sides unless the user specifies otherwise.
- Track every action in order, including skipped sets and user-performed extra sets or exercises. An explicit report of extra work is enough to record it, even for an unlisted exercise; mark it unplanned and separately ask whether it should enter the approved catalog for future plans. Use repwerk-approve-exercise if the user wants that. Do not block historical logging on approval.
- You may suggest changing future actions; ask before applying a suggested change to the active prescription. A clear user-requested change needs no second confirmation. Keep the original plan intact and represent revised targets as session-specific deviations in the result. Template changes require a separate explicit request and a new saved version through repwerk-plan.
- Correct a reported actual in context (or in the saved checkpoint) rather than adding a duplicate action.
- At user request, checkpoint the full current session as `in_progress` in a single JSON file. On resumption, read it and its referenced plan, reconstruct completed actions, and continue. If context was lost before a checkpoint, explain that unsaved results cannot be recovered.
- At finish, save the full result as `completed`, including work performed even if some planned sets were skipped or never reached. Use `abandoned` only when the user explicitly abandons the workout. Write/update one file per session, not one per set. Distinguish unknown/unperformed planned sets from explicitly skipped ones.
- If a concrete ambiguity or friction point suggests a simple refinement, briefly flag it after saving the session and ask whether the user wants the workflow changed. Do not interrupt logging, propose speculative optimizations, or modify trainer instructions without approval.
